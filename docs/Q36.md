# Qwen3.8-27B on one Arc Pro B70: `strata-q36` (optional)

A second engine in this repository, for the **dense** [Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B) (GGUF architecture
`qwen35`) on the same card. It is a separate binary, `strata-q36`. It is off by default; `strata` (Flash-Next, the engine this fork
is for, [B70.md](B70.md)) does not need it and runs as before.

**Status by this fork's bar** (128K-256K context, at least 1,000 tokens/s reading the prompt, at least 10 tokens/s answering):
**works, not usable at 128K and above.** It fits 262,144 tokens and answers at 37 tok/s (after a 128K prompt) and 19 tok/s (after a
256K prompt), but it reads those prompts at 974 and 721 tok/s. At short context it is fast (1,716 tok/s on a 2,048-token prompt,
64-75 tok/s answers with the MTP draft).

Every number on this page was **measured on 2026-11-03 on the branch this engine was written on, on one B70. None was re-measured on
this tree.** This tree got the engine by a port that was done by reading the code: nothing was built or run for it yet. If the
first build of `strata-q36` fails, that is a port error, not a known limit.

## What it is

- `sycl/src/qwen35/q36_engine.dp.cpp` (the engine), `q36_kernels.dp.hpp` (its decode kernels), `q36_prefill.dp.hpp` (prompt attention
  and the prompt's GDN recurrence), `q36_tla_fmha.cpp` (the long-prompt attention library), and `src/qwen35/` (the entry point and a
  host-side requantizer). It began as a SYCLomatic migration of a CUDA engine and has been edited by hand since.
- It speaks the same serve protocol as `strata` (`READY`, `GEN`, `T`, `DONE`, `STOP`), so `serve/server.py` serves it with
  `sycl/serve/strata-sycl.sh` and the usual API.
- It shares the kernel library with `strata`. The decode kernels it tuned for the 27B's shapes (the 17,408-wide `ffn_down` read in
  two pieces or two parts, a persistent grid for every format, KREG for Q3_K and IQ4_NL, an SLM table for the wide IQ4_NL kernel)
  are in `sycl/src/kernels/cuda/native_mmvq.dp.cpp` behind `native_mmvq_set_dense_mode(true)`. Only `strata-q36` calls it, so
  `strata` launches what it launched before.
- `strata` itself refuses a `qwen35` file and says to use this engine.

## Model files

Unsloth's [Qwen3.8-27B-GGUF](https://huggingface.co/unsloth/Qwen3.8-27B-GGUF): `Qwen3.8-27B-UD-Q4_K_M.gguf` (16.5 GB) and
`Qwen3.8-27B-UD-Q4_K_XL.gguf` (17.6 GB; it carries one IQ3_S `ffn_down`, which the native kernels take). The MTP block (`blk.64.nextn.*`) is in the
same file. 64 layers plus the MTP block, 5,120 wide, a 17,408-wide FFN, 24 query heads over 4 KV heads of 256. No other file is
needed.

## Build

One extra step for the long-prompt attention (LP3, an AOT build for Battlemage): it compiles against two upstream projects that are
not in this repository. Fetch them once (pinned commits, about 40 MB; [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) has the
licences):

    bash sycl/tools/get-q36-tla.sh

Then, in the same container as the README's build:

    docker run --rm -u $(id -u):$(id -g) -v "$PWD/..:/work" -e AOT=bmg-g31 -e Q36=ON -e REPO=/work/$H \
        -e BUILD_DIR=/work/$H/build-sycl-aot strata-sycl-dev "cd /work/$H && bash sycl/tools/build.sh strata-q36"

(`H=$(basename "$PWD")` as in the README.) The build makes `build-sycl-aot/strata-q36` and `build-sycl-aot/libq36_tla.so` beside
it; the binary finds the library through its run path, wherever the folder is mounted. The libraries it shares with `strata` are
built too; `strata` itself is not, and `build.sh` without `Q36=ON` builds the same targets from the same source lists as before. Without an `AOT` of
`bmg-*` or `lnl-*` there is no LP3 and nothing to fetch (the 8-bit cache's prompts then take the engine's own attention, slower).
If `third_party/` is missing, CMake stops and says to run the script.

## Run

1. The tokenizer, once, from the GGUF (it writes `<out>/tokenizer/`, with the model's chat template):

       python3 tools/strata_tokenizer.py --gguf /path/to/models/Qwen3.8-27B-UD-Q4_K_M.gguf --out /path/to/data/qwen38-27b

2. A config: copy `tools/qwen35/serve-27b.json` (32,768 cells), `serve-27b-128k.json` or `serve-27b-256k.json` and replace the
   `/path/to/` placeholders (the model, its folder, and `<out>/tokenizer`). The model folder must be mounted into the container: `STRATA_SYCL_MOUNTS` names it, or keep it under the
   repository's parent folder (mounted at `/work`). The config carries `"STRATA_SYCL_NAME"`, the container's name; **give it a name of
   its own**, because `strata-sycl.sh` removes a container of that name before it starts one, and the default name is the one a
   Flash-Next server uses.
3. The server, from the repository folder:

       python3 serve/server.py --engine strata --config /path/to/serve-27b.json --port 8131

   The 27B takes up to 26.7 GiB of the card at 262,144 cells: stop a Flash-Next engine first. The server ends engines that an earlier
   server left running; `STRATA_KEEP_LEFTOVERS=1` turns that off, for a start beside another server.

The API name is `qwen3.8-27b`; its sampling defaults are the GGUF's (temperature 1.0, top-p 0.95, top-k 20 when thinking).
By hand, one prompt: `tools/qwen35/q36_sycl_run.sh --model <gguf> --tokens <ids|@file> --n 64` (`Q36_MODELS` names the model's folder).

## What it does

- **Cache.** FP16 K/V by default (69.6 KB a cell); the 8-bit cache (`--kv int8`, Flash-Next's int8 format: int8 codes with one FP16
  scale per 64 values) is the default above `--max-context 131072`. At 262,144 cells it is 8.77 GiB, and the engine fits the card.
  `STRATA_Q36_KV=f16|f32|q8` overrides the flag.
- **MTP draft.** The model's own MTP block drafts 3 tokens a step by default (`--mtp N`, 0-7; `--mtp 0` is plain decode). The draft
  head reads a 64K-token vocabulary (`tools/qwen35/q36_draft_vocab_64k.json`; `--draft-vocab`, `--draft-tokens`). The verify window
  gives the plain greedy decode's tokens (checked for `--mtp` 2 to 7 on the two localmaxxing prompts).
- **Decode.** The KREG matrix-vector kernels (on for this model; `STRATA_MMVQ_KREG=0` turns them off), GQA attention shared over the 6
  query heads of a KV head, decode-side GDN kernels, a prompt chunk of 2,048 tokens when VRAM allows (then 1,024, 512).
- **Long prompts.** For the 8-bit cache, chunks run through vllm-xpu-kernels' Xe2 `chunk_prefill` on sycl-tla (LP3): the layer's K/V
  is dequantized to FP16 in 32,768-cell segments, each segment's output merged by log-sum-exp. `STRATA_Q36_PATTN=lp2` keeps the
  engine's own flash kernel, `gemm` the GEMM path (FP16/FP32 cache only).

## Measured (2026-11-03, the branch it was written on; not re-measured on this tree)

One B70, `--mtp 3`, greedy. The file: UD-Q4_K_M for the two long-prompt rows and the VRAM row (the commit says so); for the other
rows it was not written down (the port's first milestones and serve configs used UD-Q4_K_XL).

| What | Result |
| --- | --- |
| Answers, the two localmaxxing prompts (reasoning-v1 / code-v1), short context | 74.9 / 64.2 tok/s (43.3 / 42.2 ms a step) |
| Answers, plain (`--mtp 0`) | 27.1 tok/s |
| Prompt of 2,048 tokens | 1,716 tok/s |
| Prompt of 131,072 tokens, `--max-context 262144`, 8-bit cache, chunk 2,048 | 974.0 tok/s, first token after 134.6 s; the answer 36.7 tok/s |
| Prompt of 262,080 tokens, same settings | 721.3 tok/s, first token after 363.3 s; the answer 19.3 tok/s |
| Peak VRAM at `--max-context 262144` | 26.68 GiB (26.49 before LP3) |
| Against llama.cpp's Vulkan build on the same GGUF (`tools/qwen35/kl.py`) | KL 0.0005 |
| LP3 against the engine's own flash kernel on the 128K and 256K prompts | the same 64 greedy tokens; KL 0.00017 / 0.00027 |

LP3's step: the 128K prompt from 728 to 974 tok/s, the 256K prompt from 477 to 721 tok/s.

## Switches

| Variable | Default | Does |
| --- | --- | --- |
| `STRATA_Q36_KV` | by `--kv`, else by context | `f16`, `f32` or `q8` K/V cache |
| `STRATA_Q36_PATTN` | `chunk_prefill` (8-bit cache, LP3 build), else the flash kernel | `lp2`: the engine's own flash kernel; `gemm`: the GEMM path |
| `STRATA_Q36_TLA_SEG` | 32768 | LP3's segment, in cells (a multiple of 64) |
| `STRATA_Q36_CHUNK` | by free VRAM | prompt chunk, 256-4096 |
| `STRATA_Q36_ATT_CHUNKS` | 96 | the decode attention's chunk target, 8-128 |
| `STRATA_Q36_GDN_XE`, `_GDN_DEC`, `_GDN_AB2`, `_RMS_FAST` | on | `0`: the earlier kernel of that part |
| `STRATA_MMVQ_KREG` | 1 (this engine sets it) | `0`: the earlier decode kernels |
| `STRATA_KREG_KS`, `_H2`, `_H2W`, `_Q3K`, `_IQ4NL`, `_RG`, `_WAVES` | see `native_mmvq.dp.cpp` | the KREG forms; `STRATA_KREG_KS=4` is opt-in (not faster, and it moved two near-tie answers of the KL check) |
| `STRATA_DEQUANT_WIDE` | on for this engine | `0`: the plain prompt dequantizer |
| `STRATA_Q36_DUMP_MTP=1` | off | with `--dump-full-logits`: the MTP run's logits, comparable byte for byte with a plain run |

## Not done

- 5-8 column verify windows: `--mtp` 4 and 5 were still slower than 3 at the last measurement, because the windows they need run in
  256-register forms that are slow on the B70.
- Reading a long prompt: 974 tok/s at 128K is 2.6% under the bar, 721 tok/s at 256K is 28% under. The prompt attention was the last
  part replaced (LP3); what is left in it was not measured.
- The Q5_K and IQ4_XS matrix-vector kernels are the least efficient of the formats the model uses (about 81% and 68% of the card's
  bandwidth at the last measurement).
- One request at a time was measured. `--batch N` exists in the engine and was not measured; this fork's rule is one stream.
- Pictures (`--vision`) are wired in the engine and were not tried.
- The server's disk sessions (`SAVE` / `RESTORE`) and `VRAM` commands (`POST /v1/vram`, `vram_elastic`) are not implemented in the
  engine: it answers `ERR`, and the server then ends the engine and starts it again. Leave those features off.
- Qwen3.6-35B-A3B (`qwen35moe`) is in the engine's source and is not built or run here.

## Reading the source

Comments in the engine's sources name the steps the engine was made in: M2 the decode and MTP kernels (an FP16 cache and the GQA
attention too), M3 the prompt path, the serve wiring and 128K, M4 the 5-8 column windows and the long-prompt kernels. LP2 is the
engine's own head-256 prompt attention for the 8-bit cache, LP3 the `chunk_prefill` one that replaced it as the default.

## Checking it

`tools/qwen35/parity.py --q36` (greedy tokens against llama.cpp) and `tools/qwen35/kl.py` (teacher-forced KL) take
`tools/qwen35/q36_sycl_run.sh` as the reference binary and a `q36_llama_dump` built from `tools/qwen35/q36_llama_dump.cpp` against
llama.cpp (`tools/qwen35/q36_llama_vk.sh` runs it with the Vulkan backend). The kernel check for the 27B's forms:
`STRATA_PARITY_DENSE=1 mmvq_kreg_parity --selftest` (built with `PARITY=ON`). Tests without the engine:
`python3 -m pytest serve/test_q36_dense.py -q`.
